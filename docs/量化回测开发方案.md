## 一、目标与范围

### 1.1 本次需求

1. **选股日参数化**：KDJ双金叉页面增加「选股日」参数，按指定交易日（as-of）执行选股；增加「保存选股结果」按钮。
2. **结果表设计**：新建 `kdj_gold_cross_results` 表，记录选股日、买入日、买入价、卖出日、卖出价、盈利百分比，并保留信号快照字段。
3. **选股结果页面**：展示结果表数据，支持分页、排序、筛选；支持修改买入日/买入价/卖出日/卖出价，盈亏百分比自动计算并展示。

### 1.2 不在本次范围

- 不修改 KDJ 选股因子本身（间隔窗口、死叉确认、新鲜度、K值上限等保持现状）。
- 不实施 v1.3 的「MA5/MA10/MA20 三选项」与「市值上限 10000 亿」（该两项仍为独立待办）。
- 不做自动交易、不做定时扫描、不做 AI 深度分析联动。
- 不做历史候选池快照（历史市值/退市股票还原），见「风险与边界」。

设计原则：

- **选股与查询分离**：选股只负责计算信号并可选保存；结果编辑全部在结果页面完成。
- **信号快照不可变，交易字段可编辑**：同一「选股日 + 股票代码」重复保存时只刷新信号字段，保留已填写的买入/卖出信息。
- **盈亏由数据库计算**：`profit_percent` 使用 MySQL 生成列，任何买入价/卖出价修改后自动重算，避免应用层与数据库不一致。

## 三、功能一：选股日参数化

### 3.1 页面交互

在现有参数面板新增：

| 控件 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 选股日 | `st.date_input` | 今天 | 可选范围：今天往前 2 年 ~ 今天 |
| 选股日说明 | 文本 | - | 若所选日为非交易日，自动回退到该日之前最近的交易日，并显示「实际选股交易日」 |
| 执行选股 | 按钮 | - | 调用 `scan_all(select_date=...)` |
| 保存选股结果 | 按钮 | - | 仅在有结果时显示；写入 MySQL |

执行后页面展示：

- 实际使用的选股交易日；
- 数据截断提示：`信号计算仅使用 <= 选股日的 K 线，买入日/买入价来自选股日之后的真实行情（若有）`；
- 结果表新增列：`选股日`、`买入日`、`买入价`。

### 3.2 as-of 数据切片（核心，防止未来函数）

以 `T` 表示实际选股交易日，`today` 表示当前日期：

1. **K线拉取区间**：`end = min(today, T + 10 个自然日)`；开始日期按 `T - (60 个交易日对应的自然日 + 10 天)` 估算，确保 `<= T` 的有效交易日不少于 60 根。
2. **信号计算集**：`signal_df = raw_df[raw_df.date <= T]`，不足 30 根则跳过并记录日志。
3. **指标计算**：对 `signal_df` 计算 KDJ/MA（只使用 `<= T` 的数据）。
4. **信号检测/评分**：沿用现有 `detect_double_gold_cross` 与 `score_signal`；此时 DataFrame 最后一行就是 `T`，`recent_days` 语义仍为「第二次金叉距 T 的间隔」。
5. **买入信息回填**：在 `raw_df` 中取 `date > T` 的第一根 K 线：
   - `买入日 = 该根 K 线日期`
   - `买入价 = 该根 K 线开盘价`
   - 若选股日就是最新交易日、未来行情不存在，则两者留空，由用户在结果页面填写。
6. **卖出信息**：默认留空。

> 说明：步骤 5 使用未来行情仅用于「记录实际可执行的买入价」，绝不参与信号判定；`signal_df` 与买入回填是两条独立数据路径。

### 3.3 数据源适配

| 数据源 | 现状 | 选股日改造 |
|---|---|---|
| 麦蕊 MyData | 返回全量历史前复权日线，方法内部只保留最近 N 根 | 传入足够大的 `history_days` 覆盖 `T`，本地按 `<= T` 切片；历史选股时数据新鲜度校验应以 `T` 为基准，而非今天 |
| 东财 / akshare | 支持 `start_date/end_date` | `end_date = min(today, T+10天)`，`start_date` 按 T 向前覆盖 60 个交易日 |
| 新浪日线 | 只返回最近 `datalen` 根 | `datalen` 按 T 到今天的时间跨度放大；若 T 超出可获取范围则数据不足、跳过该股 |

关键改造点：

- `mairui_client.get_daily_kline` 增加 `as_of_date` 参数（或选择器内对该场景关闭全局新鲜度校验），再校验「最新一根 K 线日期 >= T - 10 个自然日」。
- `get_kline_history` 增加 `select_date`、`include_next` 参数，返回升序 DataFrame。
- 现有「数据新鲜度 10 自然日」校验逻辑对实时选股保持不变。

`scan_all` 输出的 DataFrame 在现有列基础上增加：

| 列名 | 说明 |
|---|---|
| `选股日` | 实际选股交易日（YYYY-MM-DD） |
| `买入日` | T+1 交易日；无未来行情时为 None |
| `买入价` | T+1 开盘价；无未来行情时为 None |
| `卖出日` / `卖出价` | 默认 None，由结果页面维护 |

同时将 `最新价` 的语义明确为「选股日收盘价」，在结果表头显示为「收盘价(选股日)」。

### 3.5 候选池的历史限制（必须明确）

候选池仍来自当前时点的市值筛选（问财/东财/新浪），因此历史选股存在两类偏差：

- **幸存者偏差**：已退市股票不在当前候选池；
- **市值偏差**：使用当前市值而非选股日市值，可能漏掉/误纳股票。

本方案定位为**策略研究与交易记录**，接受该偏差；若后续需要严谨回测，二期增加「每日候选池快照表」（`kdj_candidate_pool_snapshot`）或全市场历史市值数据。

### 3.6 保存选股结果

- 按钮位置：选股结果表格下方。
- 保存内容：当前页面的全部命中行（TOP N）。
- 默认保存字段：选股日、代码、名称、市值、收盘价、两次金叉日、间隔、K/D/J、MA、止损价、评分、买入日、买入价。
- 幂等规则：唯一键 `(select_date, stock_code)`；重复保存时只更新信号快照字段，**不覆盖**已有买入日/买入价/卖出日/卖出价。
- 保存成功提示：`新增 X 条，更新 Y 条`，并提供「前往选股结果页面」按钮。

### 4.1 建库建表 DDL

### 4.3 盈亏计算口径

```
profit_percent = (sell_price - buy_price) / buy_price * 100
```

- 买入价或卖出价任一为空 → `NULL`；
- 买入价为 0 → `NULL`（避免除零）；
- 结果保留 4 位小数，页面展示保留 2 位；
- 交易成本（佣金、印花税、滑点）不计入本字段，保持「毛收益」口径；如需净收益，二期增加 `fee` 字段。

### 4.4 数据库访问模块 `kdj_gold_cross_db.py`

```python
class KdjGoldCrossDB:
    def ensure_schema(self) -> None:
        """CREATE DATABASE/TABLE IF NOT EXISTS（幂等，首次调用执行）"""

    def test_connection(self) -> Tuple[bool, str]:
        """返回 (是否连通, 描述)；超时 5 秒，用于页面启动自检"""

    def save_signals(self, select_date: date, df: pd.DataFrame) -> Tuple[int, int]:
        """批量 UPSERT，返回 (新增数, 更新数)；只更新信号字段，保留交易字段"""

    def query_page(
        self,
        filters: dict,
        sort_by: str = "select_date",
        sort_order: str = "desc",
        page: int = 1,
        page_size: int = 20,
    ) -> Tuple[pd.DataFrame, int]:
        """服务端分页查询，返回 (当页数据, 总条数)"""

    def update_trade_info(
        self,
        record_id: int,
        buy_date: Optional[date],
        buy_price: Optional[float],
        sell_date: Optional[date],
        sell_price: Optional[float],
    ) -> bool:
        """更新单条交易信息；profit_percent 由生成列自动计算"""

    def get_summary(self, filters: dict) -> dict:
        """总数、已卖出数、胜率、平均收益率（用于页面顶部指标）"""
```

实现约定：

- 使用 `pymysql`（需加入 `requirements.txt`），`DictCursor`，`utf8mb4`，连接超时 5 秒。
- 每次操作独立连接（简单可靠；结果页操作低频）。连接失败抛出统一异常，由 UI 转成可读提示。
- `ensure_schema` 用进程级标志避免每次调用重复建表；UI 启动时只做一次轻量自检。
- SQL 排序字段使用白名单映射，禁止把用户输入直接拼接进 `ORDER BY`。
- 所有写入使用参数化 SQL。

## 五、功能三：选股结果页面

### 5.1 入口与页面结构

页面结构：

```

├─ 顶部：数据库连接状态 + 汇总指标（总数 / 已卖出 / 胜率 / 平均收益率）
├─ 筛选区
│   ├─ 选股日范围
│   ├─ 代码/名称关键词
│   ├─ 状态：全部 / 未买入 / 持仓中 / 已卖出 / 数据不完整

│   ├─ 只读列：选股日、代码、名称、信号快照、盈亏百分比
```

### 5.2 筛选与排序规则

状态判定（无需存储状态列）：

| 状态 | 条件 |
|---|---|
| 未买入 | `buy_date IS NULL AND buy_price IS NULL` |
| 持仓中 | `buy_date IS NOT NULL AND buy_price IS NOT NULL AND sell_date IS NULL AND sell_price IS NULL` |
| 已卖出 | `sell_date IS NOT NULL AND sell_price IS NOT NULL` |
| 数据不完整 | 其余组合（仅填了日期或价格中的一个） |

盈亏筛选：

- 盈利：`profit_percent > 0`
- 亏损：`profit_percent < 0`
- 未填写卖出价时 `profit_percent` 为 `NULL`，仅在选择「全部」时出现。

排序白名单：

`select_date`、`stock_code`、`signal_score`、`buy_date`、`buy_price`、`sell_date`、`sell_price`、`profit_percent`、`created_at`。

分页：

- 每页条数：10 / 20 / 50（默认 20）；
- `LIMIT page_size OFFSET (page-1)*page_size`；
- 筛选条件变化时重置到第 1 页。

### 5.3 编辑与校验

使用 `st.data_editor`：

```python
disabled_cols = [所有只读列]
column_config = {
    "买入日": st.column_config.DateColumn("买入日", format="YYYY-MM-DD"),
    "买入价": st.column_config.NumberColumn("买入价", min_value=0.01, step=0.01, format="%.2f"),
    "卖出日": st.column_config.DateColumn("卖出日", format="YYYY-MM-DD"),
    "卖出价": st.column_config.NumberColumn("卖出价", min_value=0.01, step=0.01, format="%.2f"),
    "盈亏百分比": st.column_config.NumberColumn("盈亏百分比(%)", disabled=True, format="%.2f"),
}
```

保存前逐行校验：

1. 买入日与买入价必须成对填写；卖出日与卖出价必须成对填写；
2. 卖出日不得早于买入日；
3. 价格必须 > 0；
4. 日期不得晚于今天；
5. 仅有卖出信息、没有买入信息 → 拒绝保存并定位行号。

保存成功后 `st.rerun()`，盈亏百分比由数据库生成列自动更新。

### 5.4 修改保存粒度

- `st.data_editor` 只承载当前页数据；
- 点击「保存修改」时，对当页可编辑字段与原查询结果做逐行比对，仅提交发生变化且校验通过的行；
- 提交调用 `update_trade_info(record_id, ...)`，按 `id` 更新，避免代码/日期组合被误改；
- 未发生变化时不发 SQL，提示「没有修改」。

### 5.5 查询 SQL 示例

```sql
SELECT *
FROM kdj_gold_cross_results
WHERE select_date BETWEEN %s AND %s
  AND (stock_code LIKE %s OR stock_name LIKE %s)
  AND signal_score >= %s
  AND (
    CASE %s
      WHEN 'not_bought' THEN buy_price IS NULL
      WHEN 'holding' THEN buy_price IS NOT NULL AND sell_price IS NULL
      WHEN 'sold' THEN sell_price IS NOT NULL
      WHEN 'incomplete' THEN (buy_price IS NULL) <> (sell_price IS NULL)
      ELSE TRUE
    END
  )
  AND (CASE %s WHEN 'profit' THEN profit_percent > 0 WHEN 'loss' THEN profit_percent < 0 ELSE TRUE END)
ORDER BY <白名单字段> <ASC|DESC>
LIMIT %s OFFSET %s;
```

总条数使用相同 WHERE 条件的 `SELECT COUNT(*)`。
